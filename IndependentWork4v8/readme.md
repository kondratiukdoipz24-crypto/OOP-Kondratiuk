## 📌 Опис проєкту
Консольний додаток C#, що демонструє використання перевантажених конструкторів для створення гнучкого класу `Product` в системі інтернет-магазину.

---

## ⚙️ Структура класу `Product`
1. **Read-only властивості:** `Id`, `Name`, `Price`, `Category`, `StockCount`.
2. **Перевантажені конструктори:**
   - **Основний:** ініціалізує всі 5 параметрів об'єкта.
   - **Скорочений (`: this(...)`):** приймає лише `id`, `name`, `price` та встановлює за замовчуванням `Category = "Uncategorized"` і `StockCount = 0`.
   - **Конструктор копіювання (`: this(...)`):** створює дублікат існуючого об'єкта `Product`.
3. **Метод `ToString()`:** перевизначено для форматованого виводу даних товару в консоль.

## ❓ Контрольні запитання та відповіді

### 1. Навіщо потрібне перевантаження конструкторів у класі `Product`?
Перевантаження конструкторів забезпечує гнучкість при створенні об'єктів. Це дозволяє додавати товари у систему з різним рівнем деталізації: коли відома повна інформація (категорія, залишок) або коли є лише базові дані (назва та ціна).

### 2. Чому конструктор копіювання зручно реалізовувати через `: this(...)`
Використання каскадного виклику `: this(...)` дозволяє уникнути дублювання коду ініціалізації полів (принцип DRY — Don't Repeat Yourself). Уся логіка створення об'єкта зосереджується в одному основному конструкторі.

### 3. Які переваги дає read-only доступ до властивостей після створення об’єкта?
Забезпечує незмінність (immutability) об'єкта. Це гарантує, що важливі характеристики товару (наприклад, ID або назва) не будуть випадково змінені ззовні після створення екземпляра, що робить код більш безпечним та передбачуваним.

### 4. У яких випадках перевизначення `ToString()` спрощує налагодження та демонстрацію роботи класу?
Перевизначення `ToString()` дозволяє отримати зрозуміле текстове представлення стану об'єкта при передачі його у `Console.WriteLine()` або під час перегляду змінних у відлагоджувачі (debugger), замість стандартної виводимої назви типу (наприклад, `IndependentWork4v8.Product`).

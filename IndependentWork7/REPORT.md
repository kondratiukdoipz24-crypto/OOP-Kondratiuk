
# Звіт
## Самостійна робота №15

**Тема:** Делегати й лямбда-вирази: власні утиліти для колекцій.

### 1. Чому делегати корисні для створення таких утиліт?

Делегати дозволяють передавати методи як параметри. Завдяки цьому можна створити один універсальний метод і використовувати його для різних завдань. Наприклад, у Map можна передавати різні способи перетворення елементів, а у Filter — різні умови відбору.

### 2. Як лямбда-вирази спрощують виклик цих методів?

Лямбда-вирази дозволяють коротко записувати потрібну дію без створення окремого методу. Наприклад, `n => n * 2` означає, що кожне число потрібно помножити на два. Це робить код коротшим і зрозумілішим.

### 3. Порівняння власних методів із LINQ

| Власний метод | Аналог LINQ | Призначення |
|---|---|---|
| Map | Select | Перетворення елементів |
| MaxBy | MaxBy | Пошук елемента з найбільшим ключем |
| Filter | Where | Фільтрація елементів |
| ForEach | ForEach у деяких типах колекцій | Виконання дії для кожного елемента |

Власні методи допомагають зрозуміти, як працюють операції з колекціями. LINQ зручний тим, що вже містить готові реалізації багатьох операцій.

### 4. Контрольні запитання

**1. Чому делегати є зручним механізмом для передавання поведінки в узагальнені методи?**

Вони дозволяють передавати різні дії в один метод. Завдяки цьому метод можна використовувати для різних завдань без зміни його коду.

**2. У чому різниця між Func<T, TResult>, Action<T> та Predicate<T>?**

- Func<T, TResult> приймає значення і повертає результат.
- Action<T> приймає значення, але нічого не повертає.
- Predicate<T> приймає значення і повертає true або false.

**3. Які переваги дає поєднання generic-методів і лямбда-виразів під час роботи з колекціями?**

Вони дозволяють створювати універсальний код, який працює з різними типами даних. Лямбда-вирази допомагають задавати потрібну дію без написання додаткових методів.

**4. У яких випадках власні утиліти на кшталт Map чи Filter корисно реалізувати самостійно, навіть якщо існує LINQ?**

Це корисно для навчання, коли потрібно зрозуміти принцип роботи делегатів, узагальнених методів і колекцій. Також власні методи можна створювати, якщо потрібна особлива логіка, якої немає у стандартних операторах.

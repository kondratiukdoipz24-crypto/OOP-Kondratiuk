
# Звіт
## Самостійна робота №14

**Тема:** Вивчення Dictionary<TKey, TValue> та HashSet<T> у бібліотеках .NET.

**Мета:** Дослідити використання узагальнених колекцій Dictionary та HashSet у реальних проєктах і навчитися застосовувати їх у власних програмах.

## 1. Аналіз використання колекцій у відкритих проєктах

Для дослідження я обрала відкритий проєкт .NET Runtime, який містить реалізацію стандартних бібліотек платформи .NET.

### Приклад 1. Dictionary<TKey, TValue>

У файлі ToCollection.cs бібліотеки System.Linq використовується Dictionary<TKey, TValue> у методі ToDictionary.

Посилання:
https://github.com/dotnet/runtime/blob/main/src/libraries/System.Linq/src/System/Linq/ToCollection.cs

Контекст використання:
Метод ToDictionary створює словник із колекції об'єктів. Для кожного елемента визначається ключ, за яким він зберігається.

Чому використовується Dictionary:
Словник дозволяє швидко знаходити елемент за ключем. Використання List вимагало б послідовного перегляду елементів.

Складність:
- Створення словника — O(n).
- Пошук за ключем — O(1) у середньому.
- Додавання — O(1) у середньому.

Особливості:
Можна використовувати власний IEqualityComparer<TKey>. Якщо в колекції є однакові ключі, метод ToDictionary викидає виняток.

### Приклад 2. HashSet<T>

У тій самій бібліотеці System.Linq у файлі ToCollection.cs реалізовано метод ToHashSet.

Посилання:
https://github.com/dotnet/runtime/blob/main/src/libraries/System.Linq/src/System/Linq/ToCollection.cs

Контекст використання:
Метод створює множину з елементів колекції, автоматично усуваючи дублікати.

Чому використовується HashSet:
Ця колекція зберігає тільки унікальні елементи та дозволяє швидко перевіряти їх наявність.

Складність:
- Додавання — O(1) у середньому.
- Пошук — O(1) у середньому.
- Видалення — O(1) у середньому.

Особливості:
Метод ToHashSet підтримує використання IEqualityComparer<T>, який визначає правила порівняння елементів.

### Додатковий аналіз реалізації HashSet

У файлі HashSet.cs проєкту .NET Runtime реалізовано сам клас HashSet<T>.

Посилання:
https://github.com/dotnet/runtime/blob/main/src/libraries/System.Private.CoreLib/src/System/Collections/Generic/HashSet.cs

У ньому реалізовано методи Add, Contains, Remove, UnionWith, IntersectWith та ExceptWith. Це дозволяє ефективно виконувати операції над множинами.

## 2. Порівняльна таблиця колекцій

| Операція | List | Dictionary | HashSet |
|---|---|---|---|
| Додавання | O(1)* | O(1)* | O(1)* |
| Пошук за значенням | O(n) | O(n) | O(1)* |
| Пошук за ключем | N/A | O(1)* | N/A |
| Видалення | O(n) | O(1)* | O(1)* |
| Перевірка наявності | O(n) | O(1)* | O(1)* |

*O(1) — середня амортизована складність для додавання або середня складність хеш-операцій. У найгіршому випадку хеш-операції можуть мати складність O(n).

Коли використовувати:
- List — коли важливий порядок елементів та доступ за індексом.
- Dictionary — коли потрібно зберігати пари ключ-значення та швидко знаходити дані за ключем.
- HashSet — коли потрібно зберігати тільки унікальні елементи та швидко перевіряти їх наявність.

## 3. Практична реалізація

У програмі реалізовано три сценарії.

### FileMetadataCache

Для зберігання метаданих файлів використовується Dictionary<string, FileMetadata>. Кожен файл має унікальний ключ, за яким можна отримати, додати або видалити інформацію.

### TagManager

Для зберігання тегів використовується Dictionary<string, HashSet<string>>. Це дозволяє зберігати теги окремо для кожної статті та не допускати повторень.

Для роботи з множинами використано UnionWith, IntersectWith та ExceptWith.

### SearchIndex

Для пошукового індексу використовується Dictionary<string, HashSet<int>>. Ключем є слово, а значенням — множина номерів документів, у яких воно зустрічається.

Це дозволяє швидко знаходити документи за одним або кількома словами.

## 4. Висновки про вибір колекцій

Dictionary краще використовувати тоді, коли дані потрібно знаходити за унікальним ключем. Він зручніший за List для такого завдання, оскільки не потрібно перебирати всі елементи.

HashSet є оптимальним вибором, коли потрібно зберігати унікальні значення, перевіряти їх наявність та виконувати операції над множинами.

Під час використання цих колекцій потрібно враховувати правильність порівняння елементів, можливість повторення ключів та хеш-колізії.
